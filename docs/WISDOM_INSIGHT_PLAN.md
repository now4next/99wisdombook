## 1. 현재 자산 진단

### 1.1 재활용 가치가 높은 자산

| 자산 | 현황 | 평가 |
|---|---|---|
| 9부 × 11장 = **99장 골격** | `book.html`, 균등 배분 완료 | ★★★ 그대로 계승 |
| 99개 핵심 문장 + 부제 + 요약 | `data/wisdom.json` (36KB) | ★★★ 앵커로 활용 |
| 99장 본문 원고 | `book.html` 768KB | ★★☆ 분해·재활용 |
| 9부 총론 9편 | `book.html` 내 | ★★☆ 부 소개로 전환 |
| 인증 (이메일 + 카카오 OAuth) | D1 `users` | ★★★ 유지 |
| 카카오 알림 + Web Push | Cron 개인화 발송 (시·분·요일) | ★★★ 유지 |
| 보관함 + 소감 + 공유 딥링크 | `saved_wisdom`, `my-wisdom.html` | ★★★ 유지 |
| 스트릭 / 추천인 | `streak_count`, `referral_code` | ★★★ 유지 |
| 카드 이미지 합성 | `/api/wisdom/card` | ★★☆ 4종 규격으로 확장 |
| 이메일 발송 기반 | `RESEND_API_KEY` 이미 사용 중 | ★★★ 뉴스레터에 즉시 활용 |

**결론: 발송 인프라와 회원 시스템은 이미 서비스 수준입니다. 개편의 본질은 "콘텐츠 계층"입니다.**

### 1.2 구조적 한계 (개편 대상)

1. **콘텐츠가 HTML에 하드코딩** — `book.html` 768KB 단일 파일. 1000편 확장 불가.
2. **데이터 모델이 얕음** — `{id, title, subtitle, summary}` 뿐. 이미지·영상·출처·태그·발행일 없음.
3. **"책" 메타포의 한계** — 99장 고정 = 매일 발송 시 99일이면 재고 소진. **1000편이 필요한 근본 이유.**
4. **9개 언어 번역본이 유지보수 부채** — 약 3MB, 원문 1곳 수정 시 9개 파일 동시 수정.
5. **루트에 개발 로그 .md 100개 이상** — 정리 대상.
6. **출처·저작권 관리 체계 없음** — 실제 출판 칼럼으로는 결격.
7. **SNS 자동 게시 없음** — 신규 구축.
8. **`.git` 없음** — CLAUDE.md는 `git push origin main` 자동 배포를 전제하나, 현재 `wrangler pages deploy` 직접 배포로 동작.

## 2. 정보 구조 (IA) 재설계

### 2.1 3계층 구조

```
9부 (Part)          — 법칙군 / 분류 축
└─ 99장 (Chapter)   — 지혜 원문 = 불변의 앵커 문장
   └─ 10편 (Insight) — 실제 발행되는 칼럼  →  총 990편 (+ 특별편 10편 = 1000편)
```

**핵심 전환**: 99장을 "읽는 콘텐츠"에서 **"분류 축"으로 재정의**합니다.
실제 발행·발송 단위는 소주제 글(Insight) 1000편입니다.

- **99장** = 속담·격언 수준의 앵커 문장 (변하지 않음)
- **1000편** = 그 지혜를 현대 사례·데이터·실천으로 풀어낸 칼럼 (매일 1편 발송)

> 1000편 ÷ 365일 = **약 2.7년치 일일 콘텐츠 재고**

### 2.2 9부 분류 기준 재정립

기존 9부 축은 이미 완성도가 높습니다. "법칙" 서술을 **독자의 문제 상황** 기준으로 재정의해 인사이트 사이트에 맞춥니다.

| 부 | 제목 | 분류 축 | 독자의 질문 | 발송 톤 |
|---|---|---|---|---|
| 1부 | 경제와 거래의 법칙 | 자원·교환·대가 | "이 선택의 진짜 비용은?" | 의사결정 |
| 2부 | 인과와 자연의 법칙 | 원인·결과·물리 | "왜 이런 결과가 왔나?" | 구조 이해 |
| 3부 | 시간과 변화의 법칙 | 시간·순환·복리 | "지금 서둘러야 하나?" | 인내·타이밍 |
| 4부 | 인간 본성과 심리의 법칙 | 인지·편향·욕망 | "나는 왜 이러지?" | 자기 인식 |
| 5부 | 관계와 처세의 법칙 | 관계·신뢰·평판 | "이 사람을 어떻게 대할까?" | 관계 실무 |
| 6부 | 실행과 노력의 법칙 | 습관·축적·숙련 | "어떻게 시작하고 지속하나?" | 실행 |
| 7부 | 위기와 생존의 법칙 | 위험·회복·결단 | "버틸까 뛸까?" | 위기 대응 |
| 8부 | 지혜와 통찰의 법칙 | 학습·판단·메타인지 | "무엇을 모르고 있나?" | 사고법 |
| 9부 | 운명과 수용의 법칙 | 한계·수용·평정 | "받아들여야 하나?" | 내적 평화 |

각 부 11장 균등 배분(9 × 11 = 99)은 이미 확보되어 있어 변경 불필요.

### 2.3 1000편 배치 규칙 — "10 렌즈(Lens)" 체계

각 장(지혜 1개)을 **10가지 각도**로 전개해 10편을 생성합니다. 이것이 1000편을 중복 없이 뽑아내는 생산 설계도입니다.

| # | 렌즈 | 글의 역할 | 예시: "계란을 한 바구니에 담지 마라" |
|---|---|---|---|
| 1 | **원형** Origin | 기원·어원·최초 기록 | 탈무드, 대항해시대 선단 분할 |
| 2 | **과학** Science | 이론·연구·데이터 검증 | 현대 포트폴리오 이론(마코위츠) |
| 3 | **역사** History | 역사적 사건 사례 | 튤립 버블, 1997 외환위기 |
| 4 | **인물** Person | 체현한 인물 / 위반한 인물 | 버핏 vs LTCM |
| 5 | **비즈니스** Business | 기업·산업 케이스 | 단일 의존이 부른 노키아의 붕괴 |
| 6 | **일상** Daily | 직장·가정의 미시 적용 | 커리어 포트폴리오, 사이드 프로젝트 |
| 7 | **반론** Counter | 이 지혜가 틀리는 조건 | 집중이 옳은 순간 |
| 8 | **동서** East & West | 동서양 해석 차이 | 유비무환 vs 헤지 |
| 9 | **실천** Practice | 체크리스트·실행법 | 분산 점검 5문항 |
| 10 | **성찰** Reflection | 질문·묵상 | 내가 모든 것을 몰아넣은 바구니는? |

**이 체계를 채택하는 이유**
- 1000편이 **중복 없이 체계적으로** 도출됨 (생산 병목 해소)
- 독자가 "오늘은 어떤 각도"인지 예측 가능 → 구독 유지율 상승
- 렌즈별로 필요한 자료(출처·이미지·영상) 종류가 고정 → 제작 표준화
- **반론 렌즈**가 있어 교조적이지 않음 → 인사이트 매체로서의 신뢰도 확보

## 3. 글 1편의 발행 표준

> ※ "Projectinsight 사이트 참고" 요청 관련: 저장소 내 참조가 없어 해당 사이트를 확인하지 못했습니다.
> 아래는 일반 인사이트 칼럼 표준안이며, URL을 주시면 톤·레이아웃·분량을 그 기준으로 확정하겠습니다.

### 3.1 구성 (3분 읽기 = 900~1,200자)

```
┌─ 훅 Hook            1~2문장 · 스크롤을 멈추게 하는 도입
├─ 앵커 Anchor        99장 원문 1문장 · 인용 스타일
├─ 본문 Body          3단락
│    ① 사례·현상   구체적 장면과 숫자
│    ② 원리        왜 그런가 (렌즈별 깊이)
│    ③ 전환        그래서 나에게
├─ 오늘의 실천 Action  1~3줄 · 반드시 행동 가능한 것
├─ 한 줄 포장 Quotable ★ 40자 이내 · SNS/카톡 카드용 인용구
├─ 이미지             16:9 원본 → 1:1 / 9:16 자동 파생
├─ 영상·오디오        선택 · 60초 낭독 또는 관련 영상 임베드
└─ 출처 Sources       최소 1개 · 링크 + 접근일
```

**`quotable` 필드가 이 기획의 기술적 핵심입니다.** 40자 인용구가 있으면 카드 이미지 자동 생성과 SNS 자동 게시가 성립합니다.

### 3.2 콘텐츠 데이터 모델

```sql
CREATE TABLE insights (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  part_id       INTEGER NOT NULL,      -- 1~9
  chapter_id    INTEGER NOT NULL,      -- 1~99
  lens          TEXT NOT NULL,         -- origin|science|history|person|
                                       -- business|daily|counter|eastwest|
                                       -- practice|reflection
  slug          TEXT UNIQUE NOT NULL,
  title         TEXT NOT NULL,
  hook          TEXT,
  anchor_quote  TEXT,                  -- 99장 원문
  body_md       TEXT,                  -- Markdown
  action        TEXT,
  quotable      TEXT,                  -- ★ SNS/카톡 카드용 40자
  hero_image    TEXT,                  -- R2 URL (16:9)
  image_1x1     TEXT,
  image_9x16    TEXT,
  video_url     TEXT,
  audio_url     TEXT,
  reading_time  INTEGER,
  tags          TEXT,                  -- JSON 배열
  status        TEXT DEFAULT 'draft',  -- draft|review|scheduled|published
  scheduled_for TEXT,
  published_at  TEXT,
  author        TEXT,
  sources       TEXT,                  -- JSON 배열 [{title,url,accessed_at,type}]
  license_note  TEXT,
  created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 3.3 출처·저작권 규칙 (출판 칼럼 기준)

- **출처 최소 1개 필수.** `status=published` 전환 시 검증하여 0개면 발행 차단.
- **인용**: 1건 15단어 이내 + 출처 표기. 가사·전문 복제 금지.
- **이미지**: 자체 생성 / CC0 / 구매 스톡만 사용. 출처·라이선스를 DB에 기록.
- **영상**: 임베드만 허용 (재호스팅 금지).
- **과학적 주장**: 1차 문헌(논문 DOI) 우선. 2차 기사 단독 인용 지양.

## 4. 배포 파이프라인

하나의 글이 5개 채널로 자동 분기합니다.

```
insight 1편
  ├─ 웹        /insight/{slug}  · SEO · OG 카드 자동
  ├─ 이메일     매일 아침 HTML 뉴스레터        [신규]
  ├─ 카카오     기존 파이프라인 재사용
  ├─ Web Push  기존 파이프라인 재사용
  └─ SNS       Instagram / Facebook / Threads  [신규]
```

### 4.1 이메일 뉴스레터 (신규)

- **Resend API 키가 이미 존재**하므로 즉시 구축 가능
- 개인화 발송 시각: 기존 `notify_hour` / `notify_minute` / `notify_days` 재사용
- 구독 관리: 요일 선택, 일시정지, **원클릭 수신거부(법적 필수)**
- 메일 구성: 인용구 카드 이미지 → 본문 요약 → 웹 전문 링크 → 오늘의 실천

### 4.2 SNS 자동 게시 — 기술적 제약을 먼저 확인해야 합니다

| 채널 | API | 제약 (중요) |
|---|---|---|
| Facebook **페이지** | Graph API | 페이지만 가능. **개인 프로필 자동 게시는 API 폐지됨** |
| Instagram | Graph API (Content Publishing) | **비즈니스/크리에이터 계정만**, FB 페이지 연결 필수, 앱 심사 필요, 이미지 public URL 필요, 일 25건 제한 |
| Threads | Threads API | 2024년 공개. 텍스트·이미지 가능, 일 250건 |
| X (선택) | API v2 | 무료 티어 월 500건 |

**"각 사용자 본인 SNS에 자동 등재"는 2단계로 나누는 것이 현실적입니다.**

- **A안 (1차 · 즉시 가능)**
  공식 브랜드 계정 자동 게시 + 사용자는 **원탭 공유**(기존 카톡 공유 + 인스타 스토리 공유 시트).
  앱 심사 불필요, 일반 사용자 진입 장벽 없음.

- **B안 (2차 · 심사 필요)**
  사용자가 자기 IG/FB/Threads를 OAuth 연결 → 예약 자동 게시.
  Meta 앱 심사 2~6주 소요, **개인 계정은 비즈니스 계정 전환이 선행 조건** → 일반 사용자 상당수 이탈 예상.

> **권고: 일반인 대상이라면 A안을 먼저 출시하고, B안은 파워 유저 옵션으로 후행.**

### 4.3 카드 이미지 자동 생성

기존 `/api/wisdom/card`(문장 합성)를 4종 규격으로 확장합니다.

| 규격 | 용도 |
|---|---|
| 1:1 | 인스타그램 피드 |
| 9:16 | 스토리 / 릴스 / 숏폼 |
| 16:9 | OG 태그 / 웹 히어로 |
| 2:1 | 카카오톡 공유 (기존 `og-kakao.png` 규격) |

합성 요소: `quotable` + 부·장 라벨 + 브랜드 워터마크

## 6. 기술 아키텍처 전환

| 영역 | 현재 | 개편 후 |
|---|---|---|
| 콘텐츠 저장 | `book.html` 하드코딩 | **D1 `insights`** + 장문 Markdown은 R2 |
| 렌더링 | 정적 거대 HTML | 경량 정적 셸 + API (또는 빌드 타임 생성) |
| 이미지 | 없음 | **Cloudflare R2 + Images** (변형 자동) |
| 발송 | Cron (카카오·푸시) | Cron + **이메일(Resend)** + **SNS 큐** |
| 다국어 | 9개 HTML 사본 | **동결(freeze)** → 추후 `insights.lang` 컬럼으로 재개 |

**신규 필요 리소스**: R2 버킷 1개, Resend 도메인 인증(SPF/DKIM), Meta 앱(B안 시)

> 이 항목들은 Cloudflare 대시보드/CLI 작업이 필요하므로 CLAUDE.md 규칙에 따라 진행 전 별도 확인이 필요합니다.

## 7. 1000편 콘텐츠 생산 계획

현실적으로 **이 프로젝트의 최대 난관**입니다. 1000편 × 1,000자 = 약 100만자.

### 7.1 생산 라인

```
1) 렌즈 매트릭스 확정   99장 × 10렌즈 = 1000 슬롯 (제목·각도만 먼저)
2) 슬롯별 자료 수집     출처 2~3개 확보
3) 초안 생성            고정 템플릿 기반
4) 사람 검수            사실확인 · 톤 · 출처 유효성   ← 병목 구간
5) 이미지 생성/선택     R2 업로드
6) 상태 전이            review → scheduled(발행일) → published
```

### 7.2 마일스톤

| 단계 | 기간 | 산출물 | 운영 가능 기간 |
|---|---|---|---|
| **M1** | 2주 | 99장 DB 이관 + 렌즈1(원형) 99편 | 99일치 |
| **M2** | 6주 | 렌즈 2·3·9 추가 → 396편 | **13개월치** |
| **M3** | 분기별 | 렌즈 1종씩 추가 | 1000편 완성 |

> **M2(396편)만 확보해도 1편/일 발행 기준 13개월 운영이 가능합니다.**
> 즉 1000편 완성을 기다리지 않고 서비스를 출시할 수 있습니다.

### 7.3 기존 원고 재활용

`book.html`의 99장 본문(768KB)은 폐기하지 않습니다.
→ **렌즈 1(원형) · 2(과학) · 3(역사)의 원재료로 분해**하여 초안 품질을 크게 끌어올립니다.

### 9.3 남은 확인 사항

1. **9개 언어 파일 제거 방식** — `legacy/` 이동(되돌릴 수 있음) vs 완전 삭제(복구 불가). `.git`이 없어 삭제하면 되돌릴 수 없습니다.
2. **git 저장소 복원 여부** — CLAUDE.md는 `git push origin main` 자동 배포를 전제하나 현재 wrangler 직접 배포로 동작 중
3. **인프라 신설 승인** — R2 버킷, Resend 도메인 인증 (Cloudflare 대시보드 작업)
4. **브랜드 캐릭터** — PLI에는 부엉이 '플리'와 독자 호칭 '플리더'가 있습니다. 동급의 장치를 둘지는 브랜드 결정이라 목업에서는 타이포그래피만으로 처리했습니다.
