## 1. 가장 먼저 처리해야 할 리스크 — 기존 딥링크

오늘의 한 문장을 `/`에서 `/daily`로 옮기면 **이미 발송된 알림이 전부 깨집니다.**
코드를 확인한 결과 다음이 모두 루트를 가리킵니다.

```
카카오 알림   https://99wisdombook.org/?autoopen=1&ch=N
웹 푸시       /?autoopen=1&ch=N
추천인 링크   https://99wisdombook.org/?ref=CODE
```

이미 사용자 카카오톡에 남아 있는 메시지는 고칠 수 없으므로 **`/`가 계속 받아야 합니다.**

**해결:** 칼럼 홈 `/` 최상단에 호환 shim을 둔다.

```js
// index.html 맨 앞 (렌더 전)
(function () {
  var q = location.search;
  if (/[?&](autoopen|ch|memo)=/.test(q)) {
    location.replace('/daily.html' + q);   // 쿼리 그대로 전달 (ref 포함)
  }
})();
```

- `?ref=`만 있는 경우는 홈에 머무르며 추천인 코드만 저장
- 신규 발송분은 API에서 `/daily.html?...`로 직접 발행하도록 변경
- 카카오 OAuth는 `/kakao-callback.html`이라 **영향 없음** (확인 완료)

## 3. Phase B — 콘텐츠 그릇 (1~2주)

**한글 책 DB는 그대로 유지한다.** 원문은 지우지 않고 칼럼의 원재료로 쓴다.

| # | 작업 | 산출물 |
|---|---|---|
| B1 | `insights` 스키마 + D1 마이그레이션 | 칼럼 1편을 담을 그릇 |
| B2 | `book.html` 99장 본문 추출 → `data/chapters/{id}.md` | **원문 보존**, 칼럼 집필 원재료 |
| B3 | `/insight/{slug}` 렌더러 | 목업 v2 `insight.html` UI |
| B4 | admin CMS 최소판 | 10편 단위 입력 · 검수 · 발행 |

### `insights` 최소 필드

```sql
id, chapter_id(1~99), part_id(1~9), lens, slug,
title, hook, anchor_quote, body_md, action, quotable,
hero_image, reading_time, sources(JSON), status, published_at
```

`status`: `draft` → `review` → `published`
**발행 조건: 출처 1개 이상 + quotable 존재** (미충족 시 발행 차단)

## 4. Phase C — 10편 단위 순차 발행 ★핵심

### 배치 정의

**1배치 = 10편**, 장 번호 순서대로 진행한다.

| 배치 | 대상 장 | 누적 |
|---|---|---|
| 1 | 1~10장 | 10편 |
| 2 | 11~20장 | 20편 |
| … | … | … |
| 10 | 91~99장 (9편) | **99편 = 전 장 1렌즈 완료** |

> 10배치를 마치면 99장 모두가 최소 1편의 칼럼을 갖는다.
> 이후 2라운드(렌즈 2)를 같은 방식으로 반복하면 198편 → 3라운드 297편…

**보완:** 배치 1만은 9부에서 1장씩 뽑는 것도 선택지다(홈이 9색으로 채워짐).
다만 순차의 단순함이 관리에 유리해 **기본은 장 번호 순서**로 둔다.

### 1배치 작업 절차 (반복 가능한 표준)

```
① 대상 확정      N ~ N+9장
② 원재료 추출    data/chapters/{id}.md + wisdom.json의 title/subtitle/summary
③ 렌즈 배정      장별로 가장 잘 맞는 렌즈 1개 (1라운드는 원형/역사 중심)
④ 자료 조사      장당 출처 2~4개 확보 (1차 문헌 우선)
⑤ 초안 작성      훅 / 앵커 / 본문 3단(사례·원리·전환) / 실천 / quotable
⑥ 검수           사실확인 · 톤 · 출처 링크 생존 확인
⑦ 이미지         파스텔 일러스트 1장 (16:9) → 1:1 / 9:16 파생
⑧ 발행           status=published · parts 목록 배지가 초록으로 전환
```

### 진행 중 사이트 상태

- 칼럼이 있는 장 → **초록 「칼럼 공개」 배지**, 클릭 시 `/insight/{slug}`
- 아직 없는 장 → 「준비 중」 표시, 원문 링크(`book.html#chapter-N`)로 임시 연결
- 홈 최신 칼럼 그리드는 발행분만 노출 → **10편만 있어도 빈 사이트로 보이지 않음**

### book.html 은퇴 시점

99장 전부가 칼럼화되는 **배치 10 완료 시점**. 그 전까지는 "원문 보기" 경로로 유지한다.

## 6. 권장 진행 순서

```
A1~A7 (구조·디자인)      3~5일   ← 콘텐츠 없이 즉시 가능
   ↓
B1~B4 (그릇)            1~2주
   ↓
C 배치 1 (1~10장)       파일럿 — 템플릿·톤·분량 확정
   ↓
C 배치 2~10  +  D1~D4 병행
```

**배치 1을 파일럿으로 삼는 것이 핵심이다.** 10편을 만들어 보면 장당 소요 시간,
출처 확보 난이도, 적정 분량이 드러난다. 그 수치로 나머지 9배치 일정을 잡는다.

## 7. 확인 필요

1. **배치 순서** — 장 번호 순서(기본) vs 배치 1만 9부 균형
2. **1라운드 렌즈** — 장별 최적 렌즈 자동 배정 vs 전부 「원형」으로 통일
3. **`.git` 부재** — Phase A는 파일 교체가 많아 되돌릴 일이 생긴다. `git init` 권장
4. **인프라** — R2(이미지), Resend 도메인 인증. 대시보드 작업이라 별도 승인 필요
